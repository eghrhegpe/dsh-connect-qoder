# 按症状排查（看到什么 → 去哪查 → 是什么）

**这份文件是「症状入口」。** 其他文档按实现组织（`KNOWN_GAPS.md` 的标题是
`adapter.ts 的 Cordis 接线`），而坏掉的人是带着**屏幕上的一句话**来的，不是带着
模块名来的。所以这里的每一行都从**你在界面上真正看到的字**出发。

**为什么需要它：** 实测在现有文档里 grep 9 句最可能被说出口的症状，
**8 句零命中**——「显示免费」「面板空白」「保存了但没生效」「刷新了没变化」
「额度不对」「模型不全」「卡片不出现」全部搜不到。文档没错，是**索引的词汇表错了**。

> 用法：先在下面「一、症状速查」里搜你看到的那句话（**用界面上原样的字**，
> 下表左列就是文案的原文），拿到 ⚠️/①/② 编号，再去对应章节看「这是什么 / 下一步」。
> 找不到就跳到「三、实在找不到时」，那里有兜底路径。

## 一、症状速查（左列是**界面上的原文**，可直接 Ctrl+F）

### 账号与登录

| 你在界面上看到 | 多半是 | 去哪 |
|---|---|---|
| `未登录` | 读不到 Qoder 桌面端登录态 | [A1](#a1-一直显示未登录) |
| `已过期` | 登录态过期，或在线校验判定过期 | [A2](#a2-显示已过期) |
| `登录已失效——请打开 Qoder 客户端（…）重新登录，然后点「重新读取登录状态」` | 同上，这是**明确**的失效提示 | [A2](#a2-显示已过期) |
| `本地登录信息读不到：{detail}` | 解密/读取失败，`detail` 就是原因 | [A1](#a1-一直显示未登录) |

## 二、每条症状的「这是什么 / 下一步」

### A. 账号与登录

<!-- anchor: a1 -->
<a id="a1-一直显示未登录"></a>

#### A1. 一直显示 `未登录`

**先分清是哪一种**，因为下一步完全不同：

- **Qoder 客户端没装这个版本** → 国内版 `qoder-cn` 与国际版 `qoder` 是**两根平行
  的线**（AGENTS.md 三条事实 1）。只装了国内版，国际版那一栏必然空。看
  `本机没装这个版本的 Qoder 客户端` 这句有没有出现。
- **装了但没登录** → 打开对应客户端登录，回来点 `重新读取登录状态`。
- **读了但解密失败** → 文案会带 `本地登录信息读不到：{detail}`，
  `detail` 是真实原因（OSCrypt 解不开、文件被锁等）。这时候可以用环境变量 PAT
  绕过：`QODERCN_PAT`（国内）/ `QODER_PAT`（国际）。**注意**：凭据链动过 P0 事故
  （把插件目录外文件清成 NUL），动之前必读 [issues/01](../issues/01-sweep-junction-zeroing.md)、
  [02](../issues/02-plaintext-key-residue.md)。

**为什么插件读不到密码**：本插件**不持有**用户密码，它读的是 Qoder 桌面端自己的
登录态（[AGENTS.md](../../AGENTS.md) 三条事实 2）。

<!-- anchor: a2 -->
<a id="a2-显示已过期"></a>

#### A2. 显示 `已过期`

两条路会判过期，别混：

1. **本地时间戳判的** → 客户端里重登即可。
2. **`在线校验登录` 判的** → 文案是
   `在线校验发现登录已过期——在 Qoder 客户端里重新登录后点「重新读取登录状态」`。
   这是**真实的上游判定**，不是本地猜的。

⚠️ **注意区分**：如果看到的是
`Qoder 的接口返回了本插件不认识的格式——请更新插件（重新登录没有用）`，
那**不是**登录问题，是协议漂移 → 去 [issues/10](../issues/10-protocol-drift-probe.md)。
文案里「重新登录没有用」是刻意的，别去重登。

#### A3. 某个版本整个空着

对照 A1 的第一种。检查顺序：

1. 那个版本的客户端装了吗（`本机没装这个版本的 Qoder 客户端`）；
2. 装了吗但是没登录；
3. 登录了但「启用此版本」被关过 → 文案 `已关闭：该版本的模型不会出现在 DSH 的模型下拉框里`。

### B. 模型与目录

#### B1. 模型下拉框里没有我要的模型

**四种原因，按这个顺序排：**

1. **没勾选**。文案：`未勾选的模型不会出现在 DSH 的模型下拉框里。`
   勾选在卡片的「模型」区。
2. **该版本的模型开关关了**。文案：
   `已关闭：该版本的模型不会出现在 DSH 的模型下拉框里`
   —— 关掉只影响是否出现在下拉框，**登录/用量/设置都保留**。
3. **上游目录里本来就没有**。文案：
   `这个版本当前没有可展示的模型（未登录，或它的「模型」开关已关闭）。`
   或 `没找到已登录的 Qoder 应用，所以没有模型。`
4. **只是被筛掉了**。文案 `没有匹配的模型。` —— 点 `清除筛选`。

**目录从哪来**：Host 每 `CATALOG_TTL_MS` 刷新一次，卡片也会按需 `?refresh=1`。
目录刷新是 issue 04（空目录冻结）与 issue 05（时间戳不真实）的落点。

#### B2. 模型显示「免费」但其实收费

**这是真实存在过的 bug，根因值得记住**（本轮刚修）：上游的 `price_factor`
是可选字段，而三处 `Number(x) || 0` 把「上游没说」折叠成了「0」，0 又一路
渲染成 `免费`。关键在于两条**本来诚实**的降级分支都要求 factor 非有限
（`pi-model.ts` 的裸名分支、`card-model.ts` 的 `undefined` 分支），
所以它们**永远是死代码**。

**判据**：真的定价 0（或负）的模型仍显示 `免费`，那是**声明值**；没有该字段
才该不显示任何价标。所以看到 `免费` 时，去查上游那条记录到底有没有 `price_factor`。

**相关的**：错峰/标准价按**当前时刻**算，到点自动变（`错峰价 至 08:00` /
`标准价 22:00 起`）。这是**刻意的重复**：卡片按自己的钟算，以便在窗口边界
翻牌，不去读 Host 算好的字段 → [issues/09](../issues/09-card-mirrors-host-logic.md)。

<!-- anchor: b3 -->
<a id="b3-已更新时间看着是新的但内容是旧的"></a>

#### B3. `已更新（时间）` 看着是新的但内容是旧的

这**正是 issue 05** 描述的事故：刷新失败时时间戳照显，于是"已更新"是假的。
现在应该看到的是 `上次更新：{time}（刷新失败）`。

`刷新失败：{reason}` 的 `reason` 是**分类**，不是自由文本（本轮刚把它收敛成
一个可穷举的联合类型）：

| reason | 说什么 | 下一步 |
|---|---|---|
| `fetch` | 网络/传输失败 | 等一会重试 |
| `credential` | 凭据解析失败 | 重登或改 PAT |
| `no-credential` | 没有凭据 | 登录 |
| `persist` | **上游拿到了，但写盘失败** | 内存里已更新，重启会回退；下次刷新自动重试 |
| `protocol-shape-changed` | **接口格式变了，插件过时** | 更新插件——重登没用 |

⚠️ 最后一条曾经和 `fetch` 不可区分，用户会被叫去重登一个不可能有帮助的动作。

<!-- anchor: b4 -->
<a id="b4-一直转圈正在读取刷新"></a>

#### B4. 一直转圈（`正在读取…` / `正在刷新…`）

- Host 侧的凭据读取曾经是**同步**起 PowerShell（上限 30 秒），会卡住事件循环
  → [issues/07](../issues/07-credential-read-blocks-event-loop.md)（已异步化）。
- 现在若还卡，看 Host 日志而不是 F12：见
  [plugin-error-where-to-look.md](plugin-error-where-to-look.md)。

### C. 用量与签到

#### C1. 用量区域空着或数字不对

三种空，文案不同、含义不同：

- `当前账户暂无可展示的用量。` → 该账号确实没有。
- `这个版本暂时没有用量数据（未登录或尚未上线）。` → 二选一。
- `这个区域暂时读不到用量。` → **这个 region 的请求失败了**（另一个可能好的）。

**区域 = region**：双 region 各自独立，一边失败不该影响另一边。

#### C2. 额度扣得不对

看 `docs/docs-qoder-cn/计费说明.md` 与
[`Qoder CN 模型用量参考系数调整通知.md`](../docs-qoder-cn/Qoder%20CN%20模型用量参考系数调整通知.md)
—— 倍率是**上游**的规则。面板显示 `倍率` / `标准价` / `活动价`。

credits 的换算在 `normalizeQuotaBucket` / `normalizeDedicatedPackage`，
百分比启发式（`>1` 视为百分数）本轮已收敛为一处 `quotaAmountsOf`。

#### C3. 签到点不了或失败

- `每日签到暂不可用：{reason}` → 上游按机器身份门控，见
  [KNOWN_GAPS](../KNOWN_GAPS.md) §8。**这是已知的**，不是新 bug。
- `今日已签到` / `今天这份已经领过了` → 正常。
- `签到失败：{message}` → `message` 是上游原文。
- **签到成功但用量数字没动** → 曾经是被"在飞读"覆盖的 bug（已修）。若复现，
  是回归 → 对照 `test/usage.test.js` 里 `reset()` 相关用例。

### D. 保存与设置

#### D1. 保存了但没生效，重启后回退

**先看是哪一种**，因为有一个是**诚实状态**不是 bug：

| 文案 | 含义 |
|---|---|
| `已保存` | 真落盘了 |
| `已保存（未确认）` | 写了但 read-back 没验证通过 —— **诚实**，别当失败 |
| `保存失败` / `保存「…」失败：{detail}` | 真失败，`detail` 是原因 |
| `有未保存的更改` | 草稿还没提交 |

**历史事故**：假"已保存" + 不可达的 503 →
[issues/06](../issues/06-save-route-and-false-saved.md)。现在的形态是
「**只有"假成功"被编码成 `200 + ok:false`**」，见
[plugin-error-where-to-look.md](plugin-error-where-to-look.md) §3。

**排查捷径**：保存失败**不用看控制台**，面板上 `lastSave.reason` 那行就是答案。

#### D2. 动了国内版，国际版跟着变

**这是红线 4 事故，立刻停手当 bug 处理。** 双 region 是隔离的：账号、凭据、
用量、模型目录、勾选草稿全部按 region 分开。`enabledRegions` 等设置保存必须
带**完整 map**（Host 可能逐区合并、也可能整字段替换，两种都不能丢兄弟区）。

对照 `src/client/card.tsx` 里 `toggleRegion` 的注释，与
[AGENTS.md](../../AGENTS.md) 三条事实 1。

> ⚠️ 历史备注：`toggleRegion` 丢兄弟区这件事**当前不可达**（开关上有
> `disabled={toggling}` 挡着）。所以看到本条时，先确认是不是真的丢区，
> 而不是察觉到了那次"不可达"的分析。

#### D3. `已刷新，但写盘失败`

内存里是新答案，磁盘还是旧的。**重启会回退。** 下次刷新会自动重试。
这是 `persist` 这一类失败，故意与 `fetch` 分开（C3 表同理）。

### E. 卡片整体

#### E1. 卡片根本不出现或整块白屏

**去浏览器 F12**，查这两条 `console.error`：

- [`src/client/index.ts:183`](../../src/client/index.ts) —— 卡片槽注册失败
  （`card slot "..." failed to register (host provider unaffected)`）
- [`src/client/index.ts:192`](../../src/client/index.ts) —— 卡片整体加载失败
  （`client card failed to load (host provider unaffected)`）

注意两条都带 `host provider unaffected`：**卡片崩了不影响模型可用性**，
这是刻意的隔离。所以"卡片白屏但模型能用"是预期内的组合。

产物层面的坑：`lib/client.js` 若被 tree-shake 成壳会**静默**替换掉整个卡片，
所以有 REQUIRED 闸门 → [issues/03](../issues/03-client-bundle-guard.md)、
[17](../issues/17-client-source-restore.md)。**禁止手改 `lib/`。**

#### E2. 整个插件加载不了

去 Host 侧，不是 F12：

- 跑 `dsh web` 的终端 stdout/stderr
- `~/.dsh/logs/startup-*.log`

宿主版本/协议漂移的取证见 [host-version-probe.md](host-version-probe.md)。
`github:` 源安装装出来的包**必须自带 `lib/`**，否则没有宿主入口 →
[issues/19](../issues/19-lib-committed-github-install.md)。

## 三、实在找不到时

按这个顺序，**每一步都缩小范围**：

1. **分清进程**（最常犯的错）：Host 的问题不在 F12 里。见
   [plugin-error-where-to-look.md](plugin-error-where-to-look.md) §1。
2. **分清是哪一半**：卡片渲染 vs Host 注册。卡片崩了会明说
   `host provider unaffected`。
3. **分清是 region 还是全局**：一边坏一边好 = region 问题；两边都坏 = 更外层。
4. **看语义化的文案，而不是猜**：这个插件的文案是**刻意**做到自解释的
   （`已保存（未确认）`、`上次更新：{time}（刷新失败）`、
   `请更新插件（重新登录没有用）`）。文案本身就是诊断结论。

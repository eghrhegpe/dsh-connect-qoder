# ADR 0.5.0 — 砍掉 0.1.x 宿主 ABI 支持

**日期**：2026-10-03 · **状态**：已落地（0.5.0）

## 背景

插件自 0.4.x 起一个构建横跨三代宿主 ABI：

| 宿主代 | 设置宿主面 | 设置客户端面 | 命名空间 | schemastery |
|---|---|---|---|---|
| 0.1.5 及更早 | `installSection` + `setSource` 活文档 | `settingsScope.bind({ns})` | 插件名 `dsh-connect-qoder` | 无 `volatile()`（`asVolatile` 退化为 no-op） |
| 0.1.7 | `configure({auto:true})` + Loader 活 config | `configForms` | Loader 条目 id `llm-qoder` | `volatile()`（3.18.3+） |
| 0.2（现场 0.2.0-rc.2） | 同 0.1.7，但 `installSection`/`settingsScope` 已从宿主移除 | 同 0.1.7 | 同 0.1.7 | 同 0.1.7 |

取证（`probe/host-compat.mjs --grep`，2026-10-03，宿主 0.2.0-rc.2）：

- `installSection`：**零命中**（0.1.6 代 API 已移除）；
- `settingsScope`：**零命中**（客户端服务已移除）；
- `settings.configure(presentation, owner)`、`configForms.get/describe`、
  `loader/volatile-update`、`settings.mutate(ns, ops, expectedRevision)`、
  `Schema.prototype.volatile`：均在。

也就是说：0.1.x 的探测分支在 0.2 宿主上是**不可达死代码**，但它们持续
贡献了双命名空间候选、`asVolatile` 双形态与"四套命名空间说法"（P2-4）里
的两套。宿主已经单方面切代，插件的双线兼容只剩维护成本、没有服务对象。

## 决定

0.5.0 起只支持 0.2 代宿主（含 0.2.x 预发布）：

1. **宿主侧**（`src/host/index.ts`）：删 `installSection` 分支与 `QODER_SECTION`；
   设置面只注册 `configure({auto:true})`，缺失时**显式 warn**（不新增静默
   分支）；`asVolatile` 退化函数删除，四个字段直接 `.volatile()`；
   `__save` 的命名空间候选收敛为 `[settingsNs, QODER_SETTINGS_NS]`
   （live 条目 id 优先，常量兜底；`name` 与 live 值重复，去重）。
2. **客户端侧**（`src/client/index.ts`）：删 `settingsScope` 探针；
   `resolveNamespace` 从 `/qoder/i` 子串匹配改为**精确候选**
   （`dsh-connect-qoder` 或 `llm-qoder`，与宿主 `settingsNamespaceOf` 推导的
   同一对值共享同一对常量）——子串匹配会把别家插件的 `llm-qoder-*` 行误认
   为自家（`settings-save.ts` 的 `findSettingsRow` 注释早已登记过这个风险，
   客户端这里此前一直没堵）。
3. **peer 范围**：`dsh-*` 系 `>=0.2.0-rc.0 <0.3`；`schemastery ^3.18.3`；
   `pi-ai ^0.87.1`；`cordis >=4.0.4 <5.0.0`。

## 细节

- **下限为何是 `0.2.0-rc.0` 而不是 `0.2.0`**：宿主用
  `semver.satisfies(runtime, range, { includePrerelease: true })` 判兼容，
  预发布按 semver 排序低于其稳定版（`0.2.0-rc.2 < 0.2.0`）。写 `>=0.2.0`
  会把现场正在跑的 0.2.0-rc.2 拒之门外——`docs/howto/host-version-probe.md`
  第 2 条坑的同一类错误。`>=0.2.0-rc.0` 同时接纳 rc 序列与稳定版。
- **0.4.x 继续留在 0.1.x 上**：这是 0.1.x 宿主的最后兼容版；0.1.x 用户
  不要升到 0.5.0（CHANGELOG 0.5.0 已写清）。
- **砍掉不等于行为变化**：在 0.2 宿主上，被删的分支从未被执行过
  （不可达），`verify:bundle` 的行为对拍（14 probes × 8400 calls）砍前后
  必须 IDENTICAL，是这道闸。
- **保留的"旧词"**：代码注释里"0.1.6 曾用 installSection…"这类**历史性**
  陈述保留（它们是决策记录，不是活代码路径）；文档（`docs/issues/`、
  `docs/history/`）一律不改写。

## 未随本 ADR 动的

- 设置面缺失时的降级路径（只读卡片）保持；`settings.plugin.item` 旧槽位
  的注册保持（与 ABI 代无关，属插件管理页渲染面）。
- P2-4 的"推导只留一处"完全体仍受限于 client/host 两个 bundle 无法共享
  函数：现状是**两侧共享同一对精确候选值**（宿主 `settingsNamespaceOf`
  的 fallback 常量 = 客户端 `PROVIDER_NS` + `fallback`），子串推导已消失。
  若要字节级共享推导函数，得等宿主提供跨 bundle 的公共 surface。

## 验收

- `node probe/host-compat.mjs` 对 0.2.0-rc.2 全 peer 通过（pi-ai 由
  `^0.85.1` 判 FAIL 改为 `^0.87.1` 判 ok）；
- `npm run verify` 全绿（typecheck / 两道 any 审计 / build / test /
  verify:host / verify:bundle）；
- `test/peer-compat.test.js` 更新后的 ADMIT/REFUSE 与精确 peer 串门禁绿。

# 假"已保存" + 不可达的 503（同一处修复关掉两个）

**P0 · 规模 M · 依赖 —**

## 症状

**（a）假"已保存"**：卡片的 `__save` 回退路径在端点失败后走 `scope.set`，然后**从同一个 scope 快照读回**
做校验，命中就 `return null` 而不抛错；`save()` 没抛错就显示"已保存"。而 `scope.set` 在 0.1.7 上
恰好可以"更新内存快照但不落盘"——整个 `__save` 设计要消灭的场景在回退分支**原样复活**。

**（b）503 分支不可达**：主机侧 `webCtx.get('settings')` 为空的 503 分支实际打不到——路由注册在
`ctx.inject(['webServer','settings'], …)` 内部，settings 缺失时回调根本不执行、路由不存在，
客户端拿到 **404**，于是走进 (a)。

## 证据

- `lib/client.js:276-325`（自读回校验在 311-322）、`lib/client.js:1565-1583`（不抛错即"已保存"）
- `lib/client.js:1562-1563`：卡片自己写着"要么落盘、要么抛错"
- `lib/index.js:876-887`（不可达的 503）；`lib/settings-save.js:171-180`（真正会发生的 503，README 混为一谈）

## 修法

1. 把 `__save` 路由从 `ctx.inject(['webServer','settings'], …)` 挪到 `['webServer']`，
   handler 内判空 → 现存 503 分支真正可达，端点存在但如实失败，客户端不再走回退；
2. 回退路径只在"端点不存在（404，legacy 宿主）"时启用，且提示降级为"已保存（未确认）"；
   读回校验优先读文档、读不到才读快照；
3. 把 `__save` handler 抽成可测函数（与 `applySettingsSave` 同套路），让路由级断言成为可能。
